# 专利补全 Skill

## 角色定义

你是一名专利资料补全工程师。你的职责是从用户提供的飞书文档获取专利表格，下载出本地 Excel 中间版本，逐条检查独立权利要求、技术问题、技术手段、技术功效是否完整；如不完整，则仅通过 B 列对应的智慧芽超链接补齐所需内容。每处理完一条专利，必须立刻把该条结果写回本地 Excel、同步到目标飞书表格，并刷新本地状态文件；这样即使长任务中断，也能从上一条已完成记录继续恢复。最终仍需保留一份本地最终版 Excel，并将相同更新同步回输入的飞书文档。

## 审核规则

1. **智慧芽唯一入口**：只允许使用 Excel B 列已有的智慧芽超链接进入专利详情页，不得改用其他专利网站搜索、兜底或交叉补充。
2. **智慧芽原文唯一来源**：填入 Excel 的内容只能来自该专利对应的智慧芽原文页面；禁止自由发挥、常识补全、跨专利拼接或引入外部资料。
3. **独立权利要求优先**：每条专利必须先确认是否存在独立权利要求；如果 Excel 中为空或不完整，优先补全该字段。
4. **只补缺，不乱改**：已有内容完整时不覆盖；仅对缺失、明显截断或无效占位内容做补全。
5. **优先使用智慧芽站内翻译**：如果权利要求、摘要或其他关键原文是德文或其他非中文语言，必须优先使用智慧芽页面上的“翻译”按钮切换到简体中文结果，并直接采用该站内译文。
6. **禁止自译替代站内译文**：在智慧芽已提供翻译按钮的前提下，不要自行翻译专利正文；若站内译文无法取得，需标记阻塞而不是用外部翻译兜底。
7. **来源可追溯**：补全内容必须能回溯到该专利对应的智慧芽页面；拿不到依据时要明确标记阻塞原因。
8. **中间文件定位清晰**：本地 Excel 只是从飞书下载出的中间版本，不应被当作唯一输入源或唯一交付物。
9. **保持 Excel 模板**：保持原有工作表、列顺序、样式、超链接与已有批注，不新增无关列。
10. **同步一致**：本地最终版 Excel 与输入的飞书文档中的最终内容必须一致；若只完成本地回写但未同步回输入飞书文档，任务不算完成。
11. **逐条持久化状态**：每处理完一条专利，必须立即刷新本地状态文件，至少记录 row、patent_no、处理字段、本地 Excel 写回状态、飞书表格同步状态、阻塞原因、最后更新时间。
12. **断点恢复优先**：若本地状态文件已存在，必须先读取状态文件，从 `pending`、`in_progress` 或 `remote_pending` 的行继续，不得从头重复覆盖已完成行。

## 操作步骤

### Step 1 — 接收飞书输入并下载本地中间 Excel

1. 优先接收用户提供的飞书文档链接、飞书文件链接、token 或可定位该文档的上下文信息。
2. 先从飞书下载出本地 Excel 中间版本，默认放入 `tmp*/` 目录。
3. 确认需要补全的列至少覆盖以下字段：
   - B 列：专利号（带智慧芽超链接）
   - 独立权利要求 / 第一权利要求
   - 技术问题
   - 技术手段
   - 技术功效
4. 在 `tmp*/run_state/` 下创建或读取本次任务的状态文件；若状态文件已存在，则保留其中的行级进度并以此作为恢复依据。
5. 可先运行 `scripts/analyze_completion_state.py` 生成分析快照与默认 progress 文件，作为初始状态文件基础；逐条更新时再用 `scripts/update_progress_state.py` 刷新行级状态。
6. 不预读任何额外说明文件作为补全依据；补全依据只来自该飞书文档导出的 Excel 本身和智慧芽原文页面。

### Step 2 — 提取 B 列超链接

优先使用 `scripts/extract_b_hyperlinks.py`：

```bash
python3 patent-skill/scripts/extract_b_hyperlinks.py \
  tmp_lark_export/脚踢专利侵权检查结果_20260616.xlsx
```

执行要求：

1. 从第 2 行开始逐行读取本地中间 Excel 的 B 列；
2. 记录 `row`、`patent_no`、`hyperlink`；
3. 若 B 列有专利号但无超链接，标记该行为阻塞并停止对该行补全；
4. 若超链接域名不是智慧芽，视为无效输入并向用户报错。

### Step 3 — 检查每条专利是否需要补全

对每一行专利执行以下检查：

1. **独立权利要求**：为空、只有标题、明显截断、仅有“详见链接”等占位语时，判定为待补全；
2. **语言检查**：若独立权利要求或关键原文不是中文，即使字段不为空，也判定为待通过智慧芽翻译按钮补全；
3. **来源检查**：若现有内容明显不是来自智慧芽原文、带有推测性总结或无对应原文依据，判定为待重做；
4. **技术问题**：若未说明发明要解决的问题或仅有关键词，判定为待补全；
5. **技术手段**：若缺少核心步骤/模块/结构描述，判定为待补全；
6. **技术功效**：若缺少效果、优势或结果描述，判定为待补全。

若四项均完整，则跳过该行，不重复改写。

若状态文件中该行为 `done` 且本地 Excel 写回状态、飞书表格同步状态都为成功，则直接跳过，不重新抓取智慧芽页面。

### Step 4 — 通过智慧芽页面补全内容

1. 必须使用 `web-access` skill 或等价网页访问能力打开该行的智慧芽超链接；
2. 抓取以下内容：
   - 专利标题
   - 摘要
   - 权利要求全文
   - 第一项独立权利要求（如页面可直接定位）
3. 若页面无法提供支持某个字段的原文依据，则该字段不得补写，需明确标记“智慧芽原文不足，待人工处理”。
4. 若抓取到的权利要求或摘要为德文、英文、日文或其他非中文语言，先点击智慧芽页面的“翻译”按钮并切换到“简体中文”，再读取站内翻译结果。
5. 若智慧芽翻译按钮存在但当前页面未返回可读取的简体中文结果，则该字段标记“智慧芽译文不可读，待人工处理”，不要自行翻译。
6. 依据页面原文或智慧芽站内中文翻译结果提炼并补全：
   - **独立权利要求**：优先写入完整的第一项独立权利要求；若原文非中文，则写入智慧芽提供的中文翻译版本；
   - **技术问题**：用 1 句中文说明该专利试图解决的技术问题；
   - **技术手段**：用 1 至 3 句中文概括核心技术方案；
   - **技术功效**：用 1 句中文概括带来的效果或收益。

补全过程必须忠于智慧芽原文或智慧芽站内译文，不要编造页面中不存在的技术特征，不要补入原文未出现的背景知识。

### Step 5 — 逐条回写本地 Excel 并刷新本地状态

1. 用 `xlsx` skill 或 `openpyxl` 回写本地中间 Excel，但处理单位必须是**一条专利一提交**，不要攒很多行后再统一写回；
2. 每完成一条专利的内容生成后，立即只更新该行的目标单元格，不改动其他行列；
3. 保持原有字体、边框、列宽、超链接与工作表结构；
4. 写回该行后，立即保存本地 Excel，并同步刷新本地状态文件，至少记录：
   - `row`
   - `patent_no`
   - `status`：`pending` / `in_progress` / `done` / `blocked` / `remote_pending`
   - `updated_fields`
   - `local_excel_write`：`success` / `failed`
   - `feishu_sheet_sync`：`pending` / `success` / `failed`
   - `blocked_reason`
   - `updated_at`
5. 若本地 Excel 已写回成功、但飞书表格尚未同步成功，必须把该行状态标记为 `remote_pending`，以便中断后优先补齐飞书同步；
6. 必须保留一份本地最终结果 Excel，默认另存为带后缀的新文件，避免覆盖中间版本，例如：

```text
脚踢专利侵权检查结果_20260616_补全结果.xlsx
```

### Step 6 — 逐条同步回飞书表格，并保证可恢复

1. 以 Step 1 接收到的飞书文档作为唯一同步目标，不新建无关飞书副本。
2. 如果用户同时给了明确的飞书表格链接，则将该飞书表格视为当前任务的**在线主同步面**；每处理完一条专利，都要立刻把同一行同步到该飞书表格，而不是等全部专利处理完再统一上传。
3. 如果输入是飞书云盘文件，仍需保留本地最终结果 Excel；但在长任务场景下，优先把单行更新实时同步到对应飞书表格，最后再补一次整表文件级回传。
4. 如果输入是飞书文档表格或飞书电子表格，使用 `lark-sheets` / `lark-drive` / `lark-doc` 将该行更新同步到在线表格的对应行与对应列，并在状态文件中把该行 `feishu_sheet_sync` 更新为 `success` 或 `failed`。
5. 若飞书同步失败，不得静默跳过；必须把该行状态保留为 `remote_pending` 或 `blocked`，并记录失败原因，供恢复时优先重试。
6. 恢复执行时，先处理所有 `remote_pending` 行，再继续新的 `pending` 行，避免本地与飞书长期不一致。
7. 同步后抽查 1 至 2 行，确认飞书端显示内容与本地最终结果 Excel 一致。

### Step 7 — 更稳妥的长任务执行方法

1. 把任务拆成小批次执行，例如每次只处理 5 至 20 行，批次之间立即确认状态文件与飞书表格都已落盘；
2. 以“抓取智慧芽页面 → 生成该行内容 → 写本地 Excel → 同步飞书表格 → 更新状态文件”作为固定原子流程，禁止先积压大量待写结果；
3. 优先维护一份机器可读的状态文件（JSON），而不是只在对话里口头汇报进度；
4. 每次重新进入任务时，先读取状态文件并输出当前 `done` / `remote_pending` / `blocked` / `pending` 汇总，再继续执行；
5. 若在线操作不稳定，优先保证本地 Excel 与状态文件先落盘，然后只重试失败的飞书同步步骤，而不是整批专利重新处理。

### Step 8 — 输出结果

最终输出至少包含：

1. 输入的飞书文档或飞书文件标识；
2. 本地中间 Excel 路径与本地最终结果 Excel 路径；
3. 实际补全了哪些行、哪些字段；
4. 仍然阻塞的行（如 B 列无智慧芽超链接、页面无法访问、智慧芽原文不足、智慧芽译文不可读、页面缺少独立权利要求）；
5. 本地状态文件路径，以及当前 `done` / `remote_pending` / `blocked` / `pending` 汇总；
6. 回传到输入飞书文档和飞书表格的同步结果。

## 示例判定

**行内数据：**
- B 列专利号：`CN121157836A`
- B 列超链接：智慧芽专利详情页
- “独立权利要求”为空
- “技术问题”“技术手段”“技术功效”只有短语

**处理动作：**
1. 打开该行 B 列智慧芽链接；
2. 提取第一项独立权利要求全文；
3. 仅从智慧芽原文中的摘要和权利要求提炼问题、手段、功效；
4. 回写对应单元格。

**阻塞示例：**
- B 列只有专利号，没有超链接 → 标记“缺少智慧芽入口，无法补全”
- 链接跳转失败 → 标记“智慧芽页面不可访问，待人工处理”
- 智慧芽页面没有足够原文支持某字段 → 标记“智慧芽原文不足，待人工处理”
